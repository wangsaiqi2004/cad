# 装修效果图工作流（工作流指令，不是运行时）

> **定位**：本文件只是给内置助手看的工作流说明。**不存密钥、不承担安全职责、不直接发起网络请求**，
> 也不负责权限判定。HTTP、凭据读取、超时、任务状态、保存输出、错误与单次重试全部由软件运行时
> 的「受控本地请求工具」按客户自己的模型设置处理。

## 依次完成

1. **读取当前 CAD 版本**与已确认需求（面积、尺寸、房间用途、风格、预算、特殊要求），生成效果图说明；
   把用户上传的风格参考图作为「风格 / 材质 / 光照」参考输入，不作为几何依据。
2. **明确写出**：空间（如客厅 / 主卧）、视角、风格、材质、光照，以及**禁止改变的结构**——承重墙、
   门窗洞口、房间划分、关键尺寸。不要把这些约束写进可被模型忽略的附注里。
3. **依据能力测试结论选择动作**：
   - 「图片生成」通过 → 可用文生图；
   - 「图片编辑」通过 → 可用图生图 / 局部重绘；
   - **结论为不支持 / 未配置 / 测试替身时，不得选用对应动作**，并明确告诉员工「该端点不支持 X 能力」；
   - 不得假设所有 OpenAI 兼容端点都支持图像能力。
4. **优先把 CAD 视图或程序生成的布局图作为参考输入**。同时**必须如实说明**：
   图像模型可能改变结构和尺寸，**不能承诺透视效果图与 CAD 几何 / 尺寸完全一致**，
   效果图不作为施工依据。这句话要出现在提交确认与结果页，不能省略。
5. **检查生成结果**：图片必须可解码、大小合理；结果可疑或未通过检查时**请求人工确认**，
   不自动写入正式版本。失败 / 限额 / 超时 / 无效 Key 时给出可读中文原因与下一步，不自动重试、不重复提交。
6. **保存生图记录**：对应 CAD 版本号、输入图片清单、用户提示、模型名、时间、生成或编辑动作、
   结果状态；**不保存 API Key**，导出前还要做一次明文自检。

## 防重复扣费

- 每次外部付费请求绑定 `taskId + stepId + idempotencyKey`，**提交前**先落盘「已提交」记录；
- 提交前显示模型名、输入概览与「费用由公司自己的 API 账户承担」提示，等员工**显式确认**；
- 超时 → 结果**未知** → 不允许直接重提；先提供「检查结果 / 放弃并新建任务」；
- 禁止自动重试、禁止定时器补发、禁止在循环里重新提交；仅员工显式点击重试才生成新幂等键。

## 交付边界（逐条必须可见）

- V1 只做「原始结构图 + 平面布置方案」，不生成整套施工图。
- 可编辑 CAD 格式只有 DXF；不提供、不宣称 DWG，不把 DXF 改后缀叫 DWG。
- 不承诺把上传的户型图片 / PDF 自动转成带尺寸的结构化平面；校准与人工修正是正式必经步骤。
- 图像模型可能改变结构与尺寸，效果图不作为施工依据。
- 模型费用由客户自己的 API 账户承担；软件不做代付 / 余额 / 充值 / 中转，不部署公网后端。
